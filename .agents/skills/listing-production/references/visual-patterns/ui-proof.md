# UI proof pattern

## When to use
Use when an app, device UI, control surface, or setup flow is itself part of the purchase evidence.

## Shopper question
Can I actually control, configure, or understand this feature in the interface?

## Good composition
Use authentic UI evidence, one primary screen/state, readable hierarchy, and only the callouts needed to prove the message.

## Proof object
A current product UI screenshot/export or approved prototype state that directly demonstrates the claimed control or information.

## Information density
Low to medium. Keep the focal UI action readable at channel display size.

## Common failure
Invented UI, obsolete screens, unreadable multi-screen collages, or decorative device mockups that do not prove the feature.
