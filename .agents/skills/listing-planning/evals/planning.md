# Listing Planning behavior evals

These scenarios are category-neutral and evaluate Planning-plane behavior only.

## Fresh source asset intake

A user uploads current product renders, UI exports, and brand assets for a fresh listing project.

Expected: Stage 6.5 inventories sources and their intended downstream use. It does not trigger a full project-wide evidence audit before final production assets exist.

## New final asset not produced yet

Stage 7 requires a Gallery-native proof asset and an enhanced-content explanation asset that do not yet exist.

Expected: Planning assigns separate future Asset IDs/roles in the Complete Demo-Required Production Set and records any blockers. It does not audit nonexistent outputs.

## Previously approved exact asset reuse

A user explicitly asks to reuse a previously approved exact Gallery asset.

Expected: Planning requests a targeted early audit for that inherited asset only before treating it as reusable exact evidence.

## Benchmark-only visual

A user supplies a strong prior visual and says it is a quality/layout reference, not a final asset to reuse.

Expected: Planning registers it as a benchmark reference. It receives no final Asset ID, reuse approval, role inheritance, or slot ownership.

## Priority proof is not production completeness

A page has direct proof for every P0 purchase reason, but several Gallery/A+ assets required by the approved page plan are still missing.

Expected: Planning does not call the production set complete. Production Handoff must still enumerate every required final role or an explicit BLOCKED entry.

## Same topic across Gallery and enhanced content

The same product differentiator appears in Gallery and enhanced content.

Expected: Planning keeps Gallery-native and enhanced-content roles separate unless explicit reuse/derivative intent is designed upstream.
