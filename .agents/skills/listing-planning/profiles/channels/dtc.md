# Japan DTC planning profile

## Use when

Select this profile for a brand-controlled Japan-market product page, launch page, landing page, or ecommerce product experience.

## Verify before planning

Confirm:

- actual CMS and component library;
- available analytics, experimentation, personalization and localization capabilities;
- pricing, inventory, checkout, account, support and service ownership;
- performance, accessibility, privacy and legal requirements;
- desktop/mobile/app-web behavior.

## Frontend reference intake

The best Primary Reference may be the current live brand PDP, approved design system, component library, or approved redesign reference.

Ask for a preferred current Reference URL / design file / component-library reference / screenshot set. If none is supplied, inspect the current live DTC experience and relevant page types before inventing a shell.

Keep component/CMS **Platform Capability evidence** separate from **Frontend Visual evidence**. Documentation alone does not prove the intended consumer-facing presentation.

Planning captures material page sequence, conversion controls, navigation context, responsive behavior and ownership in the Channel Frontend Reference Pack. Final fidelity enforcement belongs to Hardening.

## Content roles

A DTC page may use a flexible sequence such as:

- product identity and primary promise;
- reasons to buy;
- mechanism/proof;
- use contexts;
- offer/variation selection;
- comparison;
- compatibility/service information;
- FAQ/support/CTA.

This is a planning pattern, not a fixed template. Use the current design system and conversion path.

## Planning rules

Define the minimum page sequence required to make the purchase decision. Do not reproduce marketplace modules when the DTC system provides a better native structure.

Separate product truth, brand narrative, commercial offer and service terms so volatile content can change without rewriting stable product evidence.

When locale is `ja-JP`, apply Japan localization evidence without inferring category messaging or visual preferences from country name alone.

Define mobile-first reading order, live-text preference, image/performance constraints, animation fallback and accessibility expectations before Production.

## Planning outputs

Record CMS/component constraints, page/conversion sequence, content ownership, Primary Reference, Channel Frontend Reference Pack, mobile/performance/accessibility implications, analytics/experiment needs when requested, and the Complete Demo-Required Production Set.
