# Creative-first hardening evals

These category-neutral scenarios verify that the main Skill routes work instead of carrying every responsibility in one always-on context.

## Deep strategy remains in Planning

A request to define product/offer truth, consumer strategy, VOC implications, Japan localization, or page architecture routes to `listing-planning`; the router itself does not reproduce the full strategy playbook.

## Fresh source asset intake does not trigger full audit

A fresh project's source renders/UI/brand assets are inventoried in Planning. Full project-wide evidence audit is not required before final production assets exist.

## Complete production set precedes Stage 8

Planning must define every Demo-required final asset role before Production starts. Priority proof coverage alone cannot mark Stage 8 ready or complete.

## Production receives one-job Asset Packet

Stage 7.5–8 receives the Creative Strategy Kernel, Production Handoff, current one-job Asset Packet, referenced source assets, and approved benchmarks/patterns rather than the full project conversation.

## Control-plane terms do not enter production prompt

Image-production context excludes Stage manifests, Project State, auditor verdicts, provenance vocabulary, Change Impact maps, and delivery parity instructions unless such words are literally consumer-facing content.

## Creative approval is separate from evidence verification

`USER_APPROVED` records marketing/creative acceptance only. Final physical identity and role/scope verification happen in Hardening.

## Mandatory full audit runs at Stage 8.5

The complete final file set enters `listing-hardening` at Stage 8.5 and is audited through `listing-evidence-auditor` before final native Demo Assembly.

## Wrong final asset is rejected before Demo Assembly

A wrong file, role mismatch, unauthorized derivative, incomplete required set, or invalid slot binding blocks final native assembly instead of being normalized by editing state to match the mistake.
