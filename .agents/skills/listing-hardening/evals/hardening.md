# Listing hardening evals

These category-neutral scenarios verify final delivery integrity without moving strategy or creative-production work into the Hardening plane.

## Creative approval cannot replace physical verification

Given a complete creative Production Freeze but no pre-demo auditor evidence, `PRE_DEMO_ASSET_GATE` remains `UNVERIFIED`; `USER_APPROVED` alone is not final-consumable evidence.

## Wrong same-name file fails exact identity

A file with the same filename but different physical SHA-256 does not inherit prior approval or exact recovery status.

## Unauthorized crop fails transform authorization

A deterministic crop/reframe is still a derivative. Without matching transform authorization, the final delivery fails the transform gate.

## Gallery asset cannot satisfy enhanced-content role by convenience

An approved Gallery-native asset is not silently reused as an enhanced-content board merely because the topic is related. Semantic role and scope must match the planned slot.

## Incomplete final asset set blocks pre-demo gate

If any required final asset is missing, invalidated, unverified, or human-review-required, the complete asset-set audit blocks final native Demo Assembly.

## Stage 9 cannot invent an interaction absent from locked plan

If the locked plan is static, Stage 9 cannot retrofit a carousel, tabs, hotspot, or other interaction and then rewrite the plan to legitimize it.

## Channel-native name requires frontend fidelity

A deliverable may be labeled channel-native only when the Primary Reference and material frontend structure/ownership evidence support `FRONTEND_FIDELITY_GATE`. Otherwise use Content Review Demo.

## Accidental demo must not rewrite source registry

If Demo Assembly consumes the wrong file or slot, fix or invalidate the implementation. Do not rewrite the source registry, approval, role, or plan to match the accidental output.

## Creative freeze and evidence audit remain separate

`PRODUCTION_FREEZE_GATE` proves the approved creative set is complete. `PRE_DEMO_ASSET_GATE` proves the exact final files are evidence-safe. Both are required for Delivery State 0.2 pre-demo hardening.
