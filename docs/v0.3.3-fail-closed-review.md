# v0.3.3 Fail-Closed Hardening Review Scope

This patch release addresses adversarial findings against v0.3.2. The implementation must fail closed for missing, empty, contradictory, stale, or self-authored evidence rather than treating `PASS + N/A` as release-ready.

## P1 scope

1. Pre-Demo audit is mandatory whenever Demo delivery is in scope; it cannot be disabled by state input.
2. Required Asset IDs are derived from the union of locked plan, implementation, slot contract, and still-required blocked roles.
3. Production Freeze must carry and validate exact `asset_id -> candidate_id -> output_ref` bindings and must fail on blockers, revision pending, stale set QA, or `ready_for_hardening=false`.
4. Release publication must consume the exact SHA of a successful validation run; build jobs are read-only and only the publish job gets contents write permission.
5. Compatibility and Codex bundles must pass their own validation after extraction.
6. Physical/standalone verification must reject truncated images, SVG/inline-style external resources, and must not treat static JavaScript keyword presence as runtime interaction proof.

## P2 scope

7. `FRONTEND_FIDELITY_GATE` becomes a canonical executable gate.
8. `PROOF_VISUAL` must carry claim/source binding and cannot become final-consumable without trusted semantic claim review.

## Additional hardening

- checksum files use download-local basenames;
- ZIPs are reproducible for identical source trees;
- packaging rejects symlinks;
- documentation uses `python3` for macOS-friendly commands;
- ambiguous Chinese phrases are not unconditional stage-transition commands.

All changes are implemented through RED -> GREEN regressions on a Draft PR. No merge without explicit user confirmation.
